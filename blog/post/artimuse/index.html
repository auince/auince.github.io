评分与理解的解耦：ArtiMuse 如何联合训练美学评估的两个目标

阅读于 2026-07-25补充于 2026-08-11
美学评估多模态评分

ArtiMuse: Fine-Grained Image Aesthetics Assessment with Joint Scoring and Expert-Level Understanding ↗

图像美学评估（Image Aesthetics Assessment, IAA）长期作为回归问题处理：输入图像，输出分数。这种设计简洁高效，但实际应用中暴露出问题——分数无法解释为何一张照片被评为 7 分而非 8 分，用户不知道应该调整构图、光影还是色彩。ArtiMuse[1] 联合训练评分与专家级美学理解，通过两阶段策略和 Token As Score 机制，在保留多模态大模型（MLLM）语言能力的同时，实现了细粒度美学评分。

核心问题是：如何在单一模型中同时支持结构化美学分析（文本输出）和精确数值评分（0-100 连续分数），而两个目标不会相互干扰？本文从训练数据构造、两阶段训练机制、Token As Score 策略三个层面展开，分析 ArtiMuse 的技术选择及其与相关工作的对比。

两阶段训练的任务分工

阅读记录中提到，ArtiMuse将8维属性文本分析与MOS评分分成两个独立训练任务，Score阶段目标token而非自然语言[1]。

第一阶段是文本预训练，使用LoRA训练模型输出8个美学属性的描述。笔记提到，笔记未取得完整8属性训练prompt，仅展示单属性示例（Overall Gestalt），其余属性提示词依赖推测[1]。

笔记中提到，第一阶段通过LoRA保留模型知识，同时学习结构化美学分析，这可能修正MLLM的正面偏差，为评分提供感知基础[1]。

第二阶段是评分微调，训练模型输出MOS分数。记录中提到，两阶段本质上都是有监督训练：第一阶段是任务特定预训练,第二阶段是下游评分微调[1]。

Token As Score策略

ArtiMuse采用Token As Score策略，使用101个现有token表示0-100分，通过概率期望避免量化损失。

阅读记录中提到，这种方法利用现有token映射0-100分数，推理时对概率分布求期望，避免词表扩展[1]。

笔记中的延展性反问指出：Token As Score采用期望值作为最终分数，是否会在分布多峰时产生不存在的中间分，削弱极端分数（如0或100）的预测能力？

ArtiMuse-10K数据集

阅读记录中提到，训练数据标注生成流程分为Type 1/2/3，每张图像配对的美学分析描述由AI生成[1]。

ArtiMuse-10K数据集覆盖5大类别。每张图像有8个属性的文字描述和一个MOS分数。笔记中提到，论文中Type1/Type2提示词原文带省略号，完整原文未完全获得，存在信息缺口[1]。

与相关工作的对比分析

将 ArtiMuse 与 DepictQA[2] 和传统感知相似度度量[3] 对比，可以更清晰地理解其定位。

DepictQA 将图像质量评估重构为三个层次化任务：描述失真类型（Description）、比较两张图像的质量（Comparison）、推理哪张图像质量更高（Reasoning）。其核心是通过语言输出模拟人类的质量判断过程，在 BAPPS（Berkeley-Adobe Perceptual Patch Similarity）基准上达到 80.3% 的准确率，接近人类表现。

两者在评估对象和输出形式上存在差异。DepictQA 评估的是图像质量（quality），关注的是失真、噪声、模糊等影响图像保真度的因素；ArtiMuse 评估的是美学价值（aesthetics），关注的是构图、色彩、情感表达等主观审美维度。DepictQA 的所有任务都输出自然语言，包括质量描述和推理过程；ArtiMuse 同时输出文本分析和数值评分，两者通过两阶段训练解耦。

LPIPS（Learned Perceptual Image Patch Similarity）[3] 使用深度特征距离衡量图像之间的感知相似度，在图像生成、超分辨率等任务中广泛用作损失函数。LPIPS 的目标是判断"两张图像在人类感知上是否相似"，而非"一张图像的美学价值有多高"。

感知相似度关注的是图像之间的像素级和特征级差异，衡量的是"这张生成图像是否足够接近真实图像"。即使两张图像都在美学上平庸，只要它们在视觉上相似，LPIPS 距离就会很小。美学价值关注的是单张图像的内在审美属性，衡量的是"这张图像在构图、色彩、情感表达上的表现"。两张 LPIPS 距离很小的图像可能具有相同的美学评分，但美学评分高的图像之间 LPIPS 距离可能很大（例如一张高对比度黑白照片和一张柔和色调风景照，二者美学价值都高但视觉特征完全不同）。

验证方向

笔记提出的验证行动包括：检查论文附录获取完整评分token映射表及8属性prompt定义；重读消融实验，确认第一阶段全参数微调与LoRA变体对评分的具体量化影响；若代码可用，复现Stage1+Stage2与仅Stage2的对比，验证文本预训练对评分的实际贡献。

延展性反问：若完全移除文本预训练阶段，ArtiMuse在8个美学属性上的专家级分析能力是否会崩塌，从而间接损害评分精度？
